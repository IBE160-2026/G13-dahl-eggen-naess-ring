# Currency review (delta): the 2026-11-22 amendments checked against live sources

**Verdict:** Most of the new Vercel wording is correct, and the `vercel.json` shape the spine names is the pattern Vercel documents for this exact case. One load-bearing claim is wrong, though. AD-10 Network says Railway's edge *appends* its peer to `X-Forwarded-For`. Railway staff said in June and again in October 2026 that the edge *strips and overwrites* `X-Forwarded-For` and `X-Real-IP`, with the first value set to the real connecting address. Behind Vercel, that address is Vercel's egress IP, not the visitor's. As written, every tester would get a Vercel address as their network key. This has to be fixed before sprint 1. The version pins have also moved again, but only by minor releases.

**Counts:** 19 verified · 2 wrong · 2 stale · 4 unconfirmed (27 items; V5 is verified for the header and unconfirmed for its placement, and is counted as unconfirmed)

---

## Top findings

1. **HIGH: AD-10's network-key chain doesn't hold (item R1).** Railway's edge replaces incoming `X-Forwarded-For`/`X-Real-IP` with the address that connected to it. Behind Vercel, that is Vercel's proxy egress. The visitor's address that Vercel put in `X-Forwarded-For` never reaches Caddy, so taking the leftmost `X-Forwarded-For` returns a Vercel IP. Every tester then shares a handful of network keys, which breaks the failed-login and sign-up limits and their privacy-neutral design. See the fix in R1.
2. **MEDIUM: "`routes` and `rewrites` can't be mixed" is no longer true, and `routes` isn't deprecated (items V1-V3).** The current `vercel.json` reference says "You can use `routes` alongside `rewrites`, `redirects`, `headers`, `cleanUrls`, and `trailingSlash`." Only the route properties `handle`, `important` and `override` are deprecated. Vercel's own "Restricting your origin to Vercel traffic" recipe uses exactly the spine's `routes` + `dest` + `transforms` shape. The spine itself doesn't depend on the old rule, but don't let anyone "fix" the config on the strength of it. `vercel.ts` (GA) is an alternative, but it is either-or: "Use only one configuration file".
3. **LOW: the caching opt-out is right, but the spine should say where it goes (items V5-V6).** Projects created on or after 2026-04-06 honour upstream cache headers on external rewrites by default. Vercel documents `x-vercel-enable-rewrite-caching: 0` only as a top-level `headers` entry. With a `routes` proxy, put it in that route's `headers` map or in a top-level `headers` rule (unconfirmed which one Vercel applies to a `routes` proxy). Either way, `Cache-Control: no-store`, `Set-Cookie` and POST each already make a response uncacheable, so the backend's `no-store` is what actually guarantees this.
4. **LOW: `fra1` has to be set; it isn't the default (item V8).** The default function region is `iad1`. Hobby may pick "any single region", so set `"regions": ["fra1"]` (or the dashboard setting) in the frontend config.
5. **LOW: version notes are stale again (items S1-S6).** FastAPI is at 0.165.0 (2026-11-18) and SQLAlchemy at 2.1.9 (2026-11-16). The other pins still hold.
