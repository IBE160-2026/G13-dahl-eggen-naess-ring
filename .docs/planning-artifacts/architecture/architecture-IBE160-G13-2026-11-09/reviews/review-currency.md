# Currency review: the spine checked against live sources

**Verdict:** The platform facts behind the spine (prices, quotas, regions, pooler port, pause rule, Data API switch, bcrypt behaviour) hold up. Several version notes are already stale, though, and three things the spine relies on have changed or are wrong: Railway's config files, Railway's log location, and how Caddy can trust Railway's edge. All three need edits before sprint 1.

**Counts:** 28 confirmed · 7 contradicted · 2 unconfirmed (37 items)

**About the earlier check.** The memlog says versions were "checked on the web 2026-11-13". But SQLAlchemy 2.1.7/2.1.8 (2026-11-03/04) and Caddy 2.11.8/2.11.9 (2026-11-04/05) were already out on that date, and the spine names neither. So that check most likely relied on aggregators or distro trackers, not the primary registries. Each "current" figure below was read from PyPI, the GitHub API or Docker Hub on 2026-11-13.

---

## Top problems (fix before sprint 1)

1. **Railway Config as Code is deprecated (item 19).** New services can't use `railway.json`/`railway.toml`, and existing files stop being read on 2026-12-01. AD-14's "Railway's `preDeployCommand`" and the healthcheck therefore need a different home: `.railway/railway.ts` (`preDeploy`, `healthcheck`) or the service settings in the dashboard.
2. **The FastAPI pin is 21 minor releases behind (item 3).** The spine says 0.141.x; the current release is 0.162.7 (2026-11-13). Releases in between change body and parameter handling that NFR-7 depends on (JSON null vs an omitted field, `extra` config on parameter models).
3. **Railway stores all logs in US West (item 34).** That includes HTTP logs with the client's source IP, kept 90 days with no opt-out. A Railway employee confirmed this on 2026-10-08. It contradicts AD-14's "Railway (EU West)" as the processor statement, and it undercuts the "access logs leave out the client address" convention.
4. **"Caddy trusts only the hosting edge" has no address range to point at (item 22).** Railway publishes no proxy CIDRs. The socket peer is in 100.64.0.0/10, which Railway says "may change at any time", and Caddy's `private_ranges` doesn't include it. The header Railway documents is `X-Real-IP`, while Caddy reads only `X-Forwarded-For` by default.
5. **Smaller stale or missing points:** Caddy is at 2.11.9, with security fixes, not 2.11.7 (item 14). SQLAlchemy is at 2.1.8 (item 6). Docker Compose is at 5.x, not "v2" (item 15). The asyncpg dialect turns URL query parameters into connect arguments, and asyncpg rejects `sslmode`, so URL normalization must handle it (item 7). The Railway Postgres fallback doesn't pin a version, and `railway run` can't reach a private Railway database (item 35).
