# Structure review: LifeMode PRD (polish pass before final)

- **Reviewed:** `prd.md` (updated 2026-11-13), 28,396 words, 1,507 lines (word_metrics.py)
- **Lens:** structure · **Reader type:** humans · **Style guide:** Microsoft Writing Style Guide
- **Reviewed on:** 2026-11-13

**Purpose and audience:** This document exists to help the team, the downstream BMAD work (UX, architecture, epics and stories), and the examiner agree on what LifeMode version one must do and why. It also gives builders and testers one stable, testable reference: FR, NFR, SM, OQ, UJ, and A IDs.

**Structure model:** Strategic/Context (Pyramid) for §0-§4 and §7-§9, with Reference/Database rules for §5-§6. Those sections are lookup material: the reader jumps to one FR or NFR, so each needs the same layout and topics shouldn't overlap.

**Overall:** the shape fits the purpose. The reading guide in §0, the FR overview table, the glossary, §3.1, the consistent FR layout (statement, Realizes, Consequences (testable), If left out), and the cut list referenced by name all help readers find things, and they should stay. Most repetition across the document is deliberate reinforcement (journeys that restate FRs, a glossary that restates rules), which is right for human readers. The findings below cover three things:

- text that will go stale the day the PRD is marked final
- facts kept in three to five places, which will drift apart at the next change
- a few places where the order or the signposting makes readers hunt

**ID and numbering stability:** none of the recommended changes renumbers a section, moves an ID, or renumbers the cut list. The few changes that would (promoting §3.1, splitting §5.4, moving FR-9b) are noted and not recommended. Row 17 renames a heading but keeps its number. GitHub heading anchors would change, so check links first.
